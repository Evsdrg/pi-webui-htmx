# F01–F19 跨仓实施方案

本轮用户已授权规划并实施。以 `htmx-css-ts-review.md` 为验收清单；桥性能 O01–O04 不混入这批功能修复。

1. 模型编辑文档在浏览器保有一个草稿（包含未保存节点），字段/JSON切换先收集当前编辑，再切视图。保存发送快照，保存期间禁重复写、允许继续编辑，完成不覆盖新草稿。桥继续校验整份文档和按稳定身份恢复秘密；重名在编辑时拒绝；重命名有打码凭据时明确拒绝隐式迁移。固定控件结构用 HTML template；草稿树的本地投影是明确例外，不引入服务端全局草稿。发现模型改为认证后的 POST HTML片段，凭据不放URL，不能静默用***作真密钥。
2. 单个 fragment 请求在 beforeRequest 登记 xhr 对应的目标/会话代次，在 beforeOnLoad（响应头之前）核对；共同目标的 hx-sync replace 保留最新意图。目录输入与成功浏览路径分开，成功交换才允许使用；旧请求不能触发OOB。文件原文仍fetch，增加AbortController及每次await后的代次检查。
3. CSS组件单源、原生dialog只在open时flex；目录form承担高度布局。顶栏使用进入keyframes（退出即时关闭，明确产品语义），不以hidden模拟无效离场过渡。修上下分隔方向及分母、持久化夹值；清理失效选择器、补徽章/三态语义；模块与片段清理释放观察器/Blob/监听。
4. 记忆分区/筛选/下一页由模板声明动作。下一页追加行并替换分页控件，hasMore由总数决定。新增只读正文片段，kind表白名单+正整数ID+长度限制；不缓存记忆正文。
5. 用反例先证明问题；跨仓测试、类型/构建/契约/对比度和1920×1080、1280×720、390px浏览器复核。正文台账逐条标实际结果与限制；提交两仓并保持工作区干净。

安全边界：不放宽远程!command限制；不引入新依赖或通用数据库写接口；不把文件/图片原文端点失败改成200；POST片段仍受Host/Origin、认证和请求大小约束。配置v1仍不承诺跨浏览器/外部CLI的CAS，保留既有明确限制。
